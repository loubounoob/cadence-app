# Étage 1 — free collection

Real TikTok hashtag (and, curated, sound) pages, read the way a signed-out
visitor's browser already reads them — no paid actor, $0 per row. Runs as a
scheduled GitHub Actions job (free minutes on a public repo) and feeds the
same discovery pipeline the paid provider does, through `/api/free-intake`
→ `/api/free-pull` → `dxIngest` in `src/discovery.js`, unmodified.

## How it was verified

Opened `https://www.tiktok.com/tag/gymtok` as a plain signed-out visitor and
watched the network: the page itself fires
`GET https://www.tiktok.com/api/challenge/item_list/?...` and gets back real
recent posts for that hashtag — author handle, follower count, bio,
verified flag, per-video stats. That request is signed client-side
(`X-Bogus`/`X-Gnarly`/`msToken`), generated by TikTok's own obfuscated JS —
which is exactly why this needs a real rendered page (Playwright) rather
than a bare server-side `fetch`, and exactly why it runs as a script, not
inside a Vercel function.

Also checked: Creative Center's public trend pages
(`ads.tiktok.com/creative/creativeCenter/trends/hashtag`) render a *signed-out
preview* of the top 3 trending hashtags — useful as a manual source of fresh
seed tags, but capped at 3 without logging in, and its own JSON API
(`cc_portal_api`, `creative_radar_api`) currently answers "no permission" or
500 when signed out. Not reliable enough to scrape unattended, so it's not
in the automated path — the hashtag/sound pages above are.

## Setup

```
npm i -D playwright-core
npx playwright install chromium
cp harvest/tags.json.example harvest/tags.json   # already committed with a starter set — edit freely
```

Vercel project env vars:
- `FREE_HARVEST_SECRET` — a long random string. Only this script and
  `/api/free-intake` ever see it; the running app never does.

GitHub repo secrets (Settings → Secrets and variables → Actions):
- `CADENCE_URL` — e.g. `https://cadence-app-amber.vercel.app`
- `FREE_HARVEST_SECRET` — the same value as above

## Run it by hand

```
CADENCE_URL=https://cadence-app-amber.vercel.app FREE_HARVEST_SECRET=xxx node harvest/free-harvest.mjs
```

## Tune it

`FREE_HARVEST_MAX_TAGS` (default 15), `FREE_HARVEST_MAX_ITEMS` per tag
(default 300), `FREE_HARVEST_SCROLLS` (default 6) — all env vars, all
adjustable without touching code. Start conservative; watch
`harvest/README.md`'s own numbers drift as TikTok's page changes, and widen
once a few runs come back clean.

## What "adjust for scale, cost, quality" means here in practice

- **Scale**: `harvest/tags.json` can hold as many hashtags as the current
  discovery job's plan needs — the workflow just works through the list,
  `MAX_TAGS_PER_RUN` at a time, on whatever schedule you set.
- **Cost**: every row queued here is $0 to the provider; the paid Apify
  runs in `src/discovery.js` only ever cover what free didn't supply for a
  given hashtag, and only up to the same per-hashtag cap as before — so the
  ceiling is unchanged, the typical spend goes down.
- **Quality**: nothing about triage (Haiku) or deep scoring (Sonnet)
  changes — a free row is judged exactly as strictly as a paid one, because
  by the time it reaches those stages it is the same shape as one.
